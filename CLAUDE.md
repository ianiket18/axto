# Working in this repo

- **No references to external projects in comments.** Axto is meant to
  read as fully standalone (see the README's own note on this). Comments
  should explain the *why* of the code they're attached to, not point at
  another repo, design doc, or prior-art project for context. If a
  comparison to something else genuinely shaped a decision, that belongs
  in a commit message or PR description, not in the source.
- **Keep comments short.** One line, occasionally two. If a comment is
  running long, it's usually a sign the code needs a better name or a
  smaller function, not a bigger comment.
- **Keep CHANGELOG entries short.** A couple of lines per release/section
  entry, stating what changed — not a design rationale or a list of every
  file touched.
